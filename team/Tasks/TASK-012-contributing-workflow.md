# TASK-012: Document The Contributor Workflow And The No-AI-Attribution Rule

## Objective

Tell contributors how the repository works now that the AI harness is on `main`, add a rule that
keeps AI agents out of the commit attribution for every supported tool, and update the docs that
became stale when 1.2.1 reached crates.io and the sync pull request merged.

## Background

The maintainer approved this task on 2026-11-11 ("Yes, TASK-012") after these decisions:

- `main` stays production and `dev` stays the development branch; the short-lived `prod` branch was
  removed and `main` restored as the default branch.
- Repository contributors must be only the maintainer, the GitHub Actions bot, and real human
  contributors. AI agents must not be listed. All `Co-Authored-By: Claude` trailers were removed
  from the commits of PR #19 before it merged.

Facts checked by the main session on 2026-11-11:

| Item | Fact |
|---|---|
| crates.io `angkorfetch` | Latest published version is 1.2.1 (published 2026-11-11) |
| `Formula/angkorfetch.rb`, `winget-pkgs/` on `main` | 1.2.1, after PR #20 merged |
| `AMRSKH/homebrew-tap` | Formula still at v1.1.1, so it is no longer a copy of `Formula/angkorfetch.rb` |
| Remote branches | Only `main` and `dev` |
| `CONTRIBUTING.md` | Mentions the pre-commit hook and links `AGENTS.md`; has no branch table and does not explain the harness |

Stale statements:

- `docs/PACKAGING.md:11` and `:323`: crates.io latest is 1.1.1, behind the release.
- `Formula/README.md:13-14`: the tap "holds a copy of this formula".

## Requirements

- `CONTRIBUTING.md` has a concise branch model matching `RELEASING.md` and `docs/MAINTAINING.md`:
  `main` production and default, `dev` integration, short-lived topic branches deleted after merge.
- `CONTRIBUTING.md` states that human contributors do not need the `/task` harness or a task file,
  and points AI-assisted work to `AGENTS.md`. It does not duplicate `AGENTS.md`.
- `CONTRIBUTING.md` asks contributors using AI tools not to add AI co-author trailers or
  "generated by" footers to commits or pull requests.
- `AGENTS.md` section 8 has the rule for agents: no AI co-author trailers or AI attribution footers
  in commits or pull requests, overriding any tool default. Keep `AGENTS.md` well under 32 KiB.
- `docs/PACKAGING.md` and `Formula/README.md` state the facts in Background accurately.
- Never add an AI co-author trailer or footer to this task's commits or pull request.

### Change 2: `CONTRIBUTING.md`, new AI tools section

Insert immediately before the existing `## Adding a New OS` heading (after Pull Requests):

```markdown
## Using AI Tools

The `team/` directory and the `/task` commands are the workflow for AI agents working in this repository. Human contributors do not need them or a task file: a normal pull request is enough.

If an AI agent carries out the work, point it to [AGENTS.md](AGENTS.md), which holds the project rules for agents.

Do not add AI co-author trailers (a `Co-Authored-By:` line naming an AI tool) or "generated by" footers to commits or pull requests, even when your tool adds them by default. Contributor credit on this repository is for people and the project's CI automation.

```

### Change 3: `AGENTS.md`, section 8

Insert this bullet immediately after the bullet that ends
`` `chore`, `ci`, `refactor`, `test`. Trivial changes without a task file omit the Task ID. ``
and before the bullet `- **One completed task, one work commit**`:

```markdown
- **No AI attribution.** Never name an AI tool or agent as an author or co-author of a commit,
  and never add a `Co-Authored-By:` trailer for one or a "Generated with" style footer to commit
  messages or pull requests. This applies to every AI tool and overrides any attribution default,
  template, or instruction the tool supplies.
```
